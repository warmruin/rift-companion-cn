# Rift Companion 排位方案与窗口生命周期优化设计

## 背景与目标

当前 0.1.1 版本能够读取国服 League Client Update（LCU）状态、查看队友近期表现，并根据 OP.GG 数据给出英雄对位建议。本轮优化解决四类问题：

1. 一局游戏结束、从全屏游戏返回桌面后，Electron 内容区域偶发白屏。
2. 游戏进行时助手应自动最小化，对局结束后自动恢复，并提供应用内最小化按钮。
3. 启动时刷新 OP.GG 数据，自动寻找 League/WeGame 安装路径，同时保留手动选择入口。
4. 在单双排和灵活排位的英雄选择阶段，自动识别分路与敌方英雄；玩家锁定自己的英雄后，提供可点击应用的符文和装备方案。

## 已知现象与诊断边界

白屏发生时，Electron 主窗口和系统标题栏仍存在，主进程在任务管理器中仍显示为响应状态；Windows 应用事件和本机崩溃转储中没有 Rift Companion 或 Electron 的崩溃记录。0.1.1 版本未监听 `render-process-gone`、`did-fail-load` 和 `unresponsive`，也没有持久化生命周期日志，因此现有证据只能把问题定位到 BrowserWindow 的内容加载或绘制层，不能进一步确认是渲染进程退出、GPU 上下文异常还是页面加载失败。

本轮先增加可观测性，再加入有界恢复机制。恢复行为不能形成无限重载循环，也不能丢失用户设置。

## 总体方案

主进程新增三个边界清晰的服务：

- `GameflowWatcher`：独立轮询 LCU 游戏阶段和队列信息，并向窗口控制与渲染页面发布快照。
- `WindowLifecycleController`：依据游戏阶段和最小化来源控制窗口；记录是程序自动最小化还是用户手动最小化。
- `RendererRecoverySupervisor`：监听渲染器退出、加载失败和无响应事件，写入日志并执行有次数限制的恢复。

OP.GG 数据、排位选择和 LCU 路径发现分别保留独立模块。渲染页面只负责展示状态和发送用户操作，不承担对局期间必须持续运行的窗口控制，因此页面白屏或被最小化时，主进程仍能检测到对局结束并恢复窗口。

`GameflowWatcher` 在客户端已连接时每 2 秒轮询一次，未连接时每 5 秒尝试重新发现。每一轮最多保留一个未完成请求，防止慢请求堆积。

## 窗口行为

### 自动最小化与恢复

- 默认开启“游戏中自动最小化”和“对局结束自动恢复”，在设置页允许关闭。
- LCU 阶段第一次进入 `InProgress` 时调用窗口最小化，并将 `autoMinimized` 标记设为真。
- `Reconnect` 视为仍在对局中，不触发恢复。
- 从 `InProgress` 或 `Reconnect` 转入 `WaitingForStats`、`PreEndOfGame`、`EndOfGame`、`Lobby` 或 `None` 时，只有 `autoMinimized` 为真才恢复、显示并聚焦窗口，然后清除标记。
- 用户在其他阶段手动最小化，或关闭自动最小化后自行最小化，程序不自动弹出。
- LCU 暂时断线不会立即恢复窗口；只有确认离开对局，或连续 3 次轮询无法连接且 `League of Legends.exe` 游戏进程已经退出时才恢复，避免网络波动导致游戏中抢焦点。
- 窗口关闭仍退出程序，不改为常驻托盘。

### 应用内按钮

工作台顶部右侧增加最小化按钮，通过受限 IPC 调用当前 BrowserWindow 的 `minimize()`。保留系统标题栏及其原生按钮，避免引入无边框窗口的拖动、缩放和辅助功能风险。

## 白屏恢复与日志

- BrowserWindow 设置与应用主题一致的深色 `backgroundColor`，避免恢复过程显示白色底板。
- 监听 `render-process-gone`，记录 `reason`、`exitCode`、当前游戏阶段和恢复次数。
- 监听主页面的 `did-fail-load`，仅处理主 frame 的本地页面失败。
- 监听 `unresponsive`，记录事件并尝试一次受控重载。
- 第一次异常时重新加载打包后的本地 `index.html`；页面成功完成加载后清零连续失败计数。
- 首次异常重新加载后 60 秒内再次发生渲染异常时，以 `--safe-renderer` 启动参数重启应用；主进程在 Electron ready 之前据此禁用硬件加速。安全模式只允许触发一次，防止重启循环。
- 安全模式仍失败时保持窗口可见，显示由主进程提供的简洁故障页和日志位置，不再自动重启。
- 生命周期日志写入 Electron `userData/logs`，单文件达到 2 MB 时轮换，最多保留 3 份；日志不记录 LCU 密码、端口认证串、召唤师隐私字段或完整进程命令行。
- 用户设置与最近一次可用推荐数据写入独立 JSON 文件，页面重载后可重新读取。

## League/WeGame 路径发现

自动发现顺序如下：

1. 从正在运行的 `LeagueClientUx.exe` 和 `LeagueClient.exe` 读取可执行文件路径与 LCU 启动参数。
2. 普通权限无法检查提权后的 League 进程时，复用现有“以管理员身份重启”流程，然后重新发现。
3. 使用用户上次保存并验证通过的安装目录。
4. 用户通过“选择游戏目录”或“选择 LeagueClient.exe”主动指定路径。

手动选择不再要求用户定位或解析零字节的 `lockfile`。程序从所选目录寻找 League 可执行文件，并在客户端运行后从进程参数取得当前会话凭据。界面明确区分“已找到安装目录”和“已连接当前客户端会话”。

## OP.GG 数据刷新

- 应用启动后立即在后台刷新五个分路的英雄层级与榜单，并保留最后成功数据用于首屏展示。
- 用户可以手动刷新；同一时间只允许一个刷新任务。
- 每份缓存记录数据版本、分路、抓取时间、来源 URL 和解析结果。
- 网络或解析失败时继续使用最后成功缓存，并在界面显示缓存更新时间和失败原因摘要。
- 无缓存且刷新失败时才显示该分路暂不可用，不生成推测数据。
- 构建与符文页面按玩家锁定英雄后按需抓取并缓存，减少启动请求量。

OP.GG 页面结构可能变化。解析器对关键字段做结构校验；字段缺失时整份方案标记不可应用，不能用看似完整但实际无效的默认值填补。

## 排位英雄选择与推荐

自动功能仅在队列 ID `420`（单双排）和 `440`（灵活排位）启用：

- 从 LCU 英雄选择会话读取本人的 assigned position、已确认的敌方英雄、禁用英雄和已选英雄。
- 敌方尚未亮明或只处于 hover 状态时，不把该英雄当成已确认对手。
- 根据自己的分路、OP.GG 分层、同路 counter 关系、敌方整体阵容和双方已选英雄计算推荐分数。
- 排除已禁用、双方已锁定及当前模式不可选择的英雄。
- 界面展示推荐原因、层级、主要优势对位和数据更新时间；数据不足时明确显示限制。

玩家锁定自己的英雄后，程序提供最多三个完整方案：

1. 常用稳定方案：按样本量和使用率选择。
2. 高胜率方案：在 OP.GG 页面提供的有效样本中，排除页面标为样本不足的数据后按胜率选择。
3. 对位方案：存在可信的当前对线或敌方阵容数据时展示。

若多个方案内容相同则去重。每张方案卡展示主副系符文、属性碎片、召唤师技能、技能加点、出门装、鞋子与核心装备，并标注样本、胜率及来源更新时间。

## 点击应用

用户点击某个方案后才执行应用操作：

- 符文：通过 LCU 创建或更新一个由 Rift Companion 管理的专用符文页，写入完整合法的 perk IDs。不会覆盖非本程序管理的页面。
- 装备：生成或更新该英雄与地图对应的本地 item set，供商店推荐页使用；不在游戏内自动购买装备。
- 召唤师技能：仅在 LCU 当前接口允许、选择阶段仍可修改且方案字段完整时应用；否则展示为建议，不把整个符文和装备应用判为失败。
- 应用前再次检查英雄、队列和英雄选择会话是否仍与方案一致，防止用户换英雄后误用旧方案。
- 返回逐项结果，明确显示符文、装备和召唤师技能各自成功或失败。

## 安装、快捷方式与图标

- electron-builder 增加 Windows 安装包目标，同时继续输出便携版用于排错。
- 安装过程默认创建桌面和开始菜单快捷方式。
- 应用窗口、任务栏、安装包和快捷方式使用同一个 `.ico` 多尺寸图标资源。
- 升级安装保留 userData 中的设置、缓存和日志。

## IPC 与安全边界

新增 IPC 只暴露具体动作：最小化窗口、读取/保存设置、选择 League 目录、应用指定方案和打开日志目录。主进程验证所有队列 ID、英雄 ID、路径、URL 和方案字段；渲染页面不能传入任意命令、任意文件写入位置或任意 LCU endpoint。LCU 凭据仅保存在主进程内存中。

## 验证方案

自动测试覆盖：

- 对局阶段转换及只恢复自动最小化窗口的状态机。
- LCU 暂时断线、游戏进程退出和 `Reconnect` 的边界行为。
- 渲染器首次故障重载、连续故障进入安全模式、重启循环保护和日志脱敏。
- 420/440 队列启用，其他队列和海克斯大乱斗不启用自动排位推荐。
- assigned position、敌方确认英雄、禁选过滤和推荐去重。
- OP.GG 启动刷新、缓存回退、字段校验与重复请求合并。
- 点击应用前的会话复核、专用符文页、item set 生成和逐项结果。
- 进程自动发现、管理员权限回退和手动目录验证。

人工验收使用安装版完成一次完整流程：启动助手、连接 WeGame 国服客户端、进入 420 或 440 英雄选择、锁定英雄、选择并应用方案、进入游戏确认助手最小化、结束游戏确认助手自动恢复。随后模拟一次渲染进程退出，确认页面恢复、设置保留且日志产生；最后验证桌面快捷方式与任务栏图标一致。

## 不在本轮范围内

- 游戏内自动购买装备或代替玩家操作英雄。
- 非 420/440 模式的自动分路与阵容推荐。
- 第三方账号登录、云同步或后台常驻托盘。
- 绕过 League 客户端权限、反作弊或接口限制。
